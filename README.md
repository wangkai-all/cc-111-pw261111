# 商品编码关联规则台

两份多语言商品数据（例如中国 GB18030 导出 + 土耳其 Windows-1254 导出）在关联前，
先在页面上**逐项**选择编码、空白、Unicode 规范化、大小写等处理规则；页面实时预览
"原始键 → 整理后的键 → 能匹配到的记录"。原始值从不被覆盖，规则只生成派生键。

纯标准库实现（Python 3.11+，无第三方依赖），前端为静态 HTML/CSS/JS。

## 运行

```bash
python3 -m app.server --port 8765
# 打开 http://127.0.0.1:8765/
```

数据存于 `data/linker.sqlite3`（自动创建，已加入 `.gitignore`）。测试：

```bash
python3 -m unittest discover -s tests
```

## 设计要点

### 1. 规则逐项选择，不统一清洗后覆盖原值

9 条规则各自独立，默认全部为"保留"：

| 规则 | 可选值 | 说明 |
| --- | --- | --- |
| 编码错误单元格 | 保留 / 跳过 | 解码出现 U+FFFD 时的处理 |
| 不可见字符 | 保留 / 移除 | Cf 类（零宽空格、BOM、软连字符） |
| 空白 | 保留 / 去首尾 ASCII / 去首尾 Unicode / 合并 / 删除全部 | NBSP、全角空格需 Unicode 变体 |
| 全角 / 半角 | 保留 / 全角 ASCII→半角 | 仅 U+FF01–FF5E 与 U+3000 |
| Unicode 规范化 | 无 / NFC / NFD / NFKC / NFKD | 组合字符合成或兼容分解 |
| 重音 / 变音符号 | 保留 / 移除 | é、ş、İ 失去区别 |
| 大小写 | 保留 / 仅 ASCII 小写 / Unicode 小写 / casefold / 土耳其语小写 | I→ı、İ→i；ß→ss |
| 标点 / 分隔符 | 保留 / 破折号统一 / 删除全部 | — |
| 前导零 | 保留 / 纯数字去零 / 数字段去零 | 00123 ≠ 123 的业务含义 |

带 `!` 的选项改变业务含义。页面顶部显示当前规则指纹；选中版本的指纹与当前
规则不一致时提示"有未保存改动"。

`app/keys.py:prepare_key` 为每个键返回 `clean` 值 + 按顺序的 `steps`
（before/after/规则/说明），因此每一行都能追溯到使用了哪些规则。

### 2. 实时预览

- 内建 18 条探针（全角、NBSP、零宽空格、组合重音、İ/ı、前导零、ß、①…），
  每条显示原始键、整理后的键、触发的规则，以及"与 N 种写法相同"的碰撞提示。
- 可输入真实编码作为自定义探针。
- 规则卡片显示该规则在已载入数据中影响的键数量（A/B 分侧计数）。

### 3. 碰撞待确认，阻断自动一对一关联

同一侧多个**不同原始写法**整理成同一个键时进入碰撞列表（id 由原始写法派生，
规则微调后仍然稳定）。每个碰撞组可选择：

- **待确认（默认）**：该组及对侧同键行进入 `blocked` 状态，只显示
  可能配对数量（本侧行数 × 对侧行数），不产生任何匹配；
- **视为同一键（合并）**：按整理后的键继续匹配；
- **按原始键区分**：改用原始值匹配；
- **排除这些行**。

### 4. 两侧重复键

重复键组显示 `A 行数 × B 行数 = 可能配对数量`。先选业务上的次级字段
（最多 2 个，如品牌代码、容量），规则同样应用于次级字段：

- 恰好 1 对次级值相等 → 确认该对（`matched_secondary`）；
- 多对相等 → 保持 `ambiguous`，列出全部候选供人工判断；
- 无相等 → 提示调整规则或字段。

20k × 20k 的组只按次级签名分桶计数，预览最多 60 对，不会展开笛卡尔积。

### 5. 规则版本与变更对比

保存版本时固化：9 条规则、关联列、次级字段、碰撞决定、两侧数据签名
（SHA-256）。选择基线版本后，"版本变更"标签显示：

- **新增匹配**：现在有、基线没有；
- **失效匹配**：基线有、现在没有（且不处于冲突）；
- **变为冲突**：基线有，现在因碰撞待确认或重复歧义被阻断；
- 若数据签名与基线不同，提示差异可能混入数据本身的变化。

运行快照可单独保存（`/api/runs`），保留完整分析 JSON。

### 6. 本地样本（中文 / 英文 / 土耳其语）

| 侧 | 编码 | 覆盖的边界情况 |
| --- | --- | --- |
| A `sample_products_cn.csv` | GB18030 | 全角字母/数字/连字符、全角空格、零宽空格、前导零、组合重音、中文名称、全角与半角同码 |
| B `sample_products_tr.csv` | Windows-1254 | `I/ı`、`İ/i`、`Ş/ş`、NBSP 尾随空白、英文名称、重复键 |

在侧卡片里切换编码即会按新编码重新解码（例如故意选错编码，出现 U+FFFD，
再由"编码错误单元格"规则跳过并计数）。样本也可直接下载
（`/api/samples/A`、`/api/samples/B`，按原始编码输出）。

### 7. 导出与追溯

`下载结果 CSV` 输出每一条匹配、碰撞候选、歧义候选、未匹配和排除行，含：

`match_key`、`key_kind`、`a_raw_key`/`a_clean_key`、`a_rule_steps`（JSON）、
`b_*`、次级字段值、`version_label`、`version_id`、`rules_fingerprint`、
完整 `rules_json`。以 `= + - @` 开头的单元格加前缀 `'`，防止表格公式注入。

页面任意行号可打开抽屉，查看原始行、原始键、整理后的键、每个清洗步骤
（规则名 + before/after），以及逐字符码位（零宽字符虚线高亮）。

## 目录

```
app/
  keys.py       规则目录、逐条变换、探针样本
  matching.py   碰撞分组、阻断、重复键、版本 diff
  samples.py    两侧内置样本（GB18030 / cp1254）
  service.py    输入校验、编排、CSV/JSON 导入、导出
  store.py      SQLite：versions / version_pairs / runs / audit
  server.py     HTTP API + 静态页面（CSP、路径校验）
  static/       页面
tests/
  test_linker.py
```

## API

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/meta` | 规则、编码、样本、碰撞选项 |
| POST | `/api/import` | `{filename, encoding, content_base64\|text}` → 解析后的侧数据 |
| POST | `/api/sample/load` | `{side, encoding}` |
| POST | `/api/rules/preview` | 规则探针预览 |
| POST | `/api/preview` | 分析（不含逐行数据，用于轻量刷新） |
| POST | `/api/analyze` | 完整分析，可带 `baseline_version_id` |
| GET/POST | `/api/versions` | 版本列表 / 保存版本 |
| POST | `/api/runs` | 运行快照 |
| POST | `/api/export/csv` | 结果 CSV |
| POST | `/api/export/rules` | 规则 JSON |
| GET | `/api/samples/{A\|B}` | 原始编码样本下载 |

请求必须是 `application/json`；CSV 行数上限 20000、列数 100，请求体 12MB。
